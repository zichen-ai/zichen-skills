# 决策型营销 · decision-marketing

先了解你实际提供什么、客户为什么购买和为什么选择你，再把有依据的购买理由自然写进内容。关键信息不清楚时，会带着判断追问；材料足够后完成你需要的稿件。

版本：0.1.0。完整执行逻辑见 [SKILL.md](SKILL.md)。

## 用途

- **内容有干货，读者看不出为什么找你。** 从你处理问题的实际动作中提炼选择依据，补进原文需要解释的位置，保留原有观点和口吻。
- **产品能做很多事，介绍时说不清客户为什么买。** 结合客户当时遇到的事、比较过的办法和你的实际帮助，选出本次最值得表达的购买理由。
- **手上有客户案例，写出来像流水账或自夸。** 找到案例中的判断、取舍和具体贡献，组织成能支持观点的短故事；效果只写到资料支持的位置。
- **客户常问价格、效果或适不适合。** 根据实际顾虑形成销售说明、文章或口播框架，让客户看清服务怎样帮助自己。
- **想在旧稿植入营销，却找不到合适材料。** 先指出适合补充的位置，再主动问相关经历或真实做法，取得依据后修改。

适用于个人创作者、经营者、实物或软件产品团队，以及代客户写内容的顾问。它会区分使用者、作者、产品提供者与最终受众，避免把顾问经历写成客户经历。

## 最简单的用法：把文件发给 AI

下载 [SKILL.md](SKILL.md)，把它上传到能读取文件的 AI 对话中，再发送下面这段话。文件名可以改为“决策型营销-直接发给AI.md”。

> 请完整读取附件并使用决策型营销技能。若能持久安装到当前工具实际读取的技能目录，请直接安装并核对，已有同名内容不同时先保留并告诉我；否则在本次对话使用，并说明使用范围。先根据我的资料判断真正的问题，缺少关键背景或案例时问我，信息足够后完成任务。

接着发你的产品介绍、原稿或具体问题，无需先填问卷。这种用法无需运行安装命令，也不需要另装 Node.js、npm 或 Git。

AI 能读取附件时，就可以按文件规则在当前对话协作。要在新对话继续使用，可以重新上传；具备持久 Skill 安装能力和相应权限的工具，可以代为安装。将文件放进临时沙盒只用于当前任务，不能据此报告已完成持久安装。工具只提供手动导入入口时，按该工具的导入步骤操作即可。

不能读取 .md 时，用文本编辑器打开并复制全文到对话里，再发送上述要求。ChatGPT 支持 Markdown 文档上传，见[文件说明](https://help.openai.com/en/articles/8555545-file-uploads-faq)。本机 Skill 的文件结构见 [Codex 文档](https://developers.openai.com/codex/skills/)和 [Claude Code 文档](https://code.claude.com/docs/en/skills)。

## 可选：使用安装命令

需要能运行命令、支持 Agent Skills 的 AI 工具，以及 Node.js 22.20 或更新版本、npm 和 Git。安装器使用固定的 `skills@1.9.0`。安装器选项见[官方说明](https://github.com/vercel-labs/skills/blob/main/docs/commands.md)。

Codex：

```sh
npx -y skills@1.9.0 add zichen-ai/zichen-skills --skill decision-marketing -g -a codex -y
```

Claude Code：

```sh
npx -y skills@1.9.0 add zichen-ai/zichen-skills --skill decision-marketing -g -a claude-code -y
```

复制对应的一整行到终端运行，即可下载并安装这个 Skill。`-g` 表示跨项目使用；只用于当前项目时去掉 `-g`。已有同名 Skill 时先保留自己的修改。安装完成后开启新对话，使用下面的调用示例。

也可以把下面这段话交给有本机操作能力的 AI 助手：

> 请从 https://github.com/zichen-ai/zichen-skills 安装 decision-marketing 到我当前使用的 AI 工具。只安装这个 Skill，保留其他已有技能。安装后检查 SKILL.md 可以读取，再告诉我怎样调用。

## 输入

可以先发一段原稿、一份产品介绍、一段客户沟通，或口述你想解决的问题，无需先填完整问卷。

已有资料中，实际产品与交付做法、目标受众、客户选购经过、原稿和修改限制最有用。缺少影响本次判断的事实时，Skill 通常每轮追问一至三个相关问题；已经说清的背景沿用。

客户材料请先删除身份和联系方式等无关信息。新产品还没有成交案例时，直接说明当前产品事实和没有案例的情况即可。

## 输出

按你的要求交付购买理由分析、原稿局部植入、完整文案、口述框架、销售问题说明或审稿意见。

信息不足时，先给当前判断和具体问题。例如，某处适合展示诊断能力，会问你实际看了什么材料、发现什么、采取什么动作。取得足够依据后再写入；不会替你虚构经历、客户结果或服务权益。

## 使用示例

安装后，在支持显式 Skill 调用的工具中输入：

> 使用 decision-marketing 决策型营销技能。下面是我的产品和原稿，请先判断这篇内容写给谁、客户为什么需要这项帮助、为什么选择我。关键背景或案例缺失时先问我；信息足够后，把一个主要购买理由自然写入原稿，保留我的观点、顺序和口吻。

随后粘贴自己的资料。Codex 中也可以用 `$decision-marketing` 明确调用。

只提炼理由：

> 使用 decision-marketing。这是我的产品介绍和三段客户沟通。帮我判断客户为什么愿意付费、为什么选我，选出最值得优先表达的理由，说明依据。先不要写文案。

改已有稿：

> 使用 decision-marketing。这段稿讲清了道理，但读者看不出我的实际帮助。请找一个适合展示我做法的位置。如果缺合适案例，问我具体经历。保留其他段落，最后给完整稿。

只有模糊需求：

> 使用 decision-marketing。我想通过内容吸引更合适的咨询，目前不知道该强调什么。请先根据已有材料判断真正卡住的地方，再问会改变判断的信息。

## 依赖

Skill 本体是 Markdown 指令，没有运行脚本、API 密钥、付费数据库或特定人物知识库依赖。你需要自己能够使用的 AI 工具；模型使用费用由对应工具决定。

通过命令安装时需要前述 Node.js、npm、Git，以及连接 npm 和 GitHub。正文执行主要使用你提供的材料；额外检索按当前任务和工具能力进行。

## 边界

它主要解决购买理由的判断与内容表达。完整市场调查、产品交付、流量投放和销售执行需要各自的资料与工作。

案例、成交、效果、价格、权益和资质来自实际材料。假设示例只能解释机制，不能写成你的亲历。客户表达的认可、付款和交付后的反馈按实际阶段使用。

收到单纯校对、翻译或改词任务时按指定范围完成。已经明确的观点和锁定原文保留。发布内容、联系客户或改变正式报价，需要对应动作的授权。

## 验证

发布前完成结构检查，以及覆盖背景不足、缺少植入案例、信息齐全、局部改词、购买理由提炼和实物商品场景的六组行为测试。实物商品样本由独立执行者设计，在本次指令冻结后才用于测试。

验证范围为对话行为、事实使用、原稿保留、交付完成和安装文件完整性。测试材料为模拟场景，真实客户的咨询和成交表现需要另行观察。
