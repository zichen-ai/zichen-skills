# 版本与验证

## 能声称什么

| 已取得的证据 | 可以报告 |
| --- | --- |
| 文件格式、命名、资源与依赖检查通过 | 结构校验通过 |
| 实际执行任务并检查成果 | 真实任务测试通过 |
| 执行者未看预期答案的留出测试和关键回归通过 | 当前留出与回归样本通过 |
| GitHub 来源实际安装成功，且资源逐项一致 | GitHub 安装与资源校验通过 |

不能把生成文件、说明中存在安装命令、自动化脚本运行成功，等同于 Skill 对用户有效。

## 每个首发 Skill 的最低行为样本

3–6 个样本应覆盖：正常输入；缺材料或条件变化的边界；相邻但不应触发的任务；执行者未看预期答案的留出任务。一个样本可覆盖多个维度。修改旧 Skill 时，另确保原来做对的关键任务没有退化。

先写可观察的评判条件，再运行样本。保存实际输入、输出、关键工具动作、结果和限制；敏感记录留在仓库外。根据失败原因做最小通用修复，重新运行受影响样本。

## 公开摘要

包内 README 与 `catalog.json` 写明实际达到的等级、运行环境、样本数量、主要限制。`validation` 的摘要由维护者根据真实证据填写；检查器不会执行模型任务，也不会自动把等级升级。

## 更新规则

每次改变包行为、触发描述或依赖，都更新版本和验证摘要。纯排版修正可用修订版本。每次安装声明都以对应仓库提交为准。未完成安装核验的更新不沿用旧版本的“安装通过”结论。
