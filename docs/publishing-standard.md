# Skill 发布规范

## 收录条件

每个 Skill 围绕一个可重复的问题，明确使用情境、输入材料、预期成果、可观察的完成证据和不处理的邻近问题。质量要求要落实为动作和边界：哪些事情必做，哪些禁止，信息不足时怎样处理，什么时候停止，什么错误直接判失败。

梓辰确认具体包与公开范围后，才从本地原件制作公开副本。工具不会自动搜索、复制或上传本地已安装的 Skills。

## 包结构

```text
skills/<name>/
  SKILL.md
  README.md
  LICENSE
  references/      按需附带必要的参考方法
  scripts/         按需附带必要脚本
  assets/          按需附带模板与资源
```

`SKILL.md` 使用 YAML frontmatter，包含 `name` 与 `description`。本仓库采用更窄的命名约定：1–64 个小写英文字母、数字、单连字符，目录名相同。为保证无需第三方依赖的检查器能可靠解析，`name`、`description` 使用单行标量；复杂多行描述在正文说明。

正文与脚本引用包内文件时使用相对路径。环境变量和由使用者提供的输入路径应在 README 中解释。不得把作者的本机文件、账号或记忆当成使用前提。

## README 必须讲清楚

固定章节：`用途`、`输入`、`输出`、`使用示例`、`依赖`、`边界`、`验证`、`许可`。示例展示真实支持的动作，不编造效果、成交数字或用户评价。人工修改、外部账号和需要付费的服务如实说明。

## 公开范围

允许：已确认的通用方法、必要脚本、原创或可再分发模板、已授权公开的示例。

不公开：真实客户材料和姓名映射、私有知识库、会话记录、评测答案、未经确认的案例、个人电脑绝对路径、凭据、缓存和运行日志。普通正则扫描无法识别全部隐私和版权问题，仍需逐文件审阅。

文件使用 UTF-8 文本；当前自动流程拒绝二进制资源、符号链接和单文件超过 1 MiB 的内容。确需图片或二进制模板时，先扩展审核规则和相应测试，不能绕过检查后直接上传。

## 来源与许可

每个 Skill 独立附带 `LICENSE`，在 README 说明原创与引用来源。直接安装的第三方 Skill 不标为原创；修改第三方 Skill 时保留必要版权信息并遵守原许可。尚未确定许可的包不能发布。

## 目录登记

`catalog.json` 登记 `name`、`path`、`version`、`summary`、`license`、`validation`。目录只列已确认的包；模板见 `templates/catalog-entry.json`。版本采用 `主版本.次版本.修订版本`，触发范围或交付发生不兼容变化时升级主版本。

发布后才提供实际核验过的安装命令。空仓库和模板文件不得宣传为已可安装的 Skill。
